# agent-memory

Постоянная память для каждого вашего проекта в Claude Code.

Claude забывает все между сессиями. agent-memory сохраняет то, что выяснилось в работе над
проектом: решения, правила, факты о коде, данных и порядке работы, и у каждого факта указан файл
или проверка, откуда он взят. Когда вы открываете новую сессию в этом проекте, Claude получает
короткую выжимку того, что действует сейчас, а с каждым запросом добавляется то, что к нему
относится. Другие проекты эту память не видят.

[English version](README.md)

## Как это работает

- Чтение автоматическое и только чтение. Два хука срабатывают при старте сессии и при каждом
  вашем сообщении. Они добавляют в контекст Claude короткий блок `<project-memory read-only="true">`.
  В память проекта хуки ничего не записывают: они ведут только небольшой кэш того, что уже показано
  в этой сессии, и файл диагностики `last_hook.json` в папке данных плагина (`${CLAUDE_PLUGIN_DATA}`).
  Текст они помечают как данные, а не как инструкции.
- Пишет один агент на задачу. В задаче, где меняют или исследуют код, тот, кто делает работу
  (основная сессия или субагент `agent-memory:executor`), открывает эпизод, а после проверки
  результата сохраняет только новое проверенное знание. Говорить "запомни" не нужно. Обычный
  разговор ничего не записывает.
- У каждой записи есть источник. Запись - одно утверждение (решение, факт, ограничение, баг)
  с доказательством: файл, коммит, тест, документ. Claude видит, насколько запись надежна прямо
  сейчас: если файл изменился или тест перестал проходить, запись помечается как требующая проверки.
- Четыре раздела: `code` (устройство, модули), `logic` (правила, решения), `data` (схемы,
  форматы, источники), `workflow` (как запускать, тестировать, выкладывать).
- Ветки и рабочие копии учитываются. Знание, записанное в другой ветке или на незакоммиченных
  правках другой рабочей копии, здесь не выдается как факт. Если факт, который Claude уже видел,
  отозван, следующая выжимка один раз об этом скажет.
- Проекты изолированы. Рабочие копии (worktree) одного git-репозитория делят одну память;
  отдельные клоны и другие проекты - нет.
- Пишущий всегда один. Пишущий держит аренду, привязанную к его процессу Claude Code. Если
  нельзя доказать, что этот процесс завершился, никто не забирает аренду без подтверждения человека.

## Что нужно

- Claude Code с поддержкой плагинов.
- Python 3.10 или новее: [python.org](https://www.python.org/downloads/), Homebrew
  (`brew install python`) или запускатель `py` в Windows. `python3` из Command Line Tools на macOS -
  версия 3.9, она слишком старая. Без подходящего Python плагин остается выключенным и один раз, при
  старте сессии, пишет, что установить. Claude он никогда не блокирует.
- git.

## Установка

В Claude Code:

```
/plugin marketplace add CRMGPT/agent-memory
/plugin install agent-memory@agent-memory
```

Из локальной папки вместо GitHub: `/plugin marketplace add /путь/к/agent-memory`.
После установки начните новую сессию. Проверить установку можно в терминале (точная команда
приходит в блоке `<memory-integration>` при старте сессии; здесь общий вид):

```
python3 "<папка плагина>/bin/launcher.py" cli doctor
```

## Как пользоваться

Ничего особенного делать не нужно, работайте как обычно. При старте сессии Claude получает от
плагина доверенный блок с точной командой памяти (`MEM`) для вашего компьютера и оболочки.
Исполнитель задачи пользуется ей так:

```
MEM begin "<задача>"                        # печатает токен сессии
MEM end --session <токен> --diff diff.json --summary "<одна строка>"
MEM session finish --session <токен>        # только когда закончена вся задача
```

`diff.json` — список новых записей, у каждой раздел и источник:
`[{"type": "FACT", "section": "code", "statement": "...", "evidence": [{"kind": "file", "ref": "path/to/file.py"}]}]`.
Изменения существующих записей — полной формой `{"ops": [...]}`, она описана в скилле.

Еще полезно: `MEM where` (какую память использует эта папка, только чтение), `MEM search "<слова>"`,
`MEM doctor`, `MEM selftest [файл]` (прогоняет тесты и пишет файл диагностики без личных путей и
без содержимого памяти). Полный порядок работы описан в скилле `agent-memory:project-memory`.

## Где лежат данные

| Система | Память проектов |
| --- | --- |
| Windows | `%LOCALAPPDATA%\agent-memory\projects\<id>\` |
| Linux, WSL | `$XDG_DATA_HOME/agent-memory/projects/<id>/` (по умолчанию `~/.local/share/...`) |
| macOS | `~/Library/Application Support/agent-memory/projects/<id>/` |

Идентификатор проекта записан в `.git/agent-memory.json` (внутри `.git`, не в ваших файлах). Папка
без git становится проектом, только если вы отметите ее командой `MEM init-project`. Кэш сессий
хуков (`sessions/`), `last_hook.json` и под Windows `wsl-paths.json` лежат в папке данных плагина,
которую выделяет Claude Code (`${CLAUDE_PLUGIN_DATA}`); памяти проектов там нет.

Проект внутри WSL, открытый в Claude Code под Windows, читается и пишется внутри WSL той же копией
плагина (внутри WSL нужен Python 3.10 или новее).

## Как выключить

- Один проект: создайте пустой файл `.agent-memory-off` в корне проекта или поставьте
  `"agent-memory@agent-memory": false` в `enabledPlugins` файла `.claude/settings.local.json`.
- Везде: `/plugin disable agent-memory@agent-memory` или удалить совсем:
  `/plugin uninstall agent-memory@agent-memory`. Память проектов при удалении остается; если она не
  нужна, удалите папки из таблицы выше.

## Если владелец неизвестен

Если пишущая сессия завершилась аварийно, следующий пишущий может получить отказ с состоянием
владельца `unknown`. Так задумано: без доказательства, что прежний процесс завершен, два пишущих
могли бы смешать работу. Убедитесь, что прежняя сессия действительно закончена, и подтвердите это
сами:

```
MEM session recover --operator-confirmed "<что вы проверили>"
```

Агент никогда не ставит этот флаг сам.

## Приватность

Не кладите в память секреты, значения из `.env`, записи клиентов и переписку. Текст в известных
форматах секретов (API-ключи, токены, закрытые ключи, `password=...`) отклоняется на любом пути
записи, и ничего не сохраняется. Но это фильтр известных форматов, а не гарантия: необычный секрет
может пройти. Память остается на вашем компьютере, плагин ничего никуда не отправляет.

## Ограничения

Проверено: Windows (нативно и с WSL). Не проверено: macOS и Linux вне WSL — поддержка не подтверждена.

- Без гарантий: это ранняя версия (0.1.1).
- Память хороша настолько, насколько хорошо в нее записали; перед тем как опереться на факт,
  проверьте указанный источник.
- Хуки добавляют ограниченный объем текста (не больше примерно 6000 знаков за событие).
